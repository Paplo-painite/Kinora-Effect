# Contributing to Kinora Effect

Thank you for helping improve Kinora Effect.

## Before opening an issue

- Check the latest release and existing issues first.
- Use a clear title.
- Include the device model, Android version, Kinora Effect version, and reproducible steps.
- Attach screenshots, logs, or a small sample project when they are safe to share.
- Do not upload private media, credentials, signing keys, or personal data.

## Feature requests

Describe the user problem first, then explain the proposed solution and why it would help. Keep requests focused so they can be discussed and reviewed clearly.

## Pull requests

1. Keep each pull request focused on one improvement.
2. Preserve the existing interface style and touch workflow unless the change explicitly concerns them.
3. Update the relevant documentation when behavior changes.
4. Test the affected workflow on an Android device or emulator when possible.
5. Explain what was tested and include any known limitations.

## Code and documentation style

Use descriptive names, small focused changes, and concise comments. User-facing documentation should be written in clear English and should describe how to use Kinora Effect rather than internal packaging details.

## Review and licensing

By submitting a contribution, you confirm that you have the right to submit it and that it can be distributed under the project’s applicable license terms. Maintainers may request changes for compatibility, clarity, security, or consistency with the project’s direction.
